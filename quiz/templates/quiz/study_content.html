Network Fundamentals › What Is a Network?

What Is a Network?

A computer network is a group of connected devices that can communicate with one another and share information or resources. A network can be very simple, such as two computers connected by a cable, or extremely large, such as the Internet.

The important idea is that connected devices can exchange data and make use of services provided by other devices.

What Is a Network Node?

A network node is a device that participates in a network. Nodes can have different roles depending on what they are doing and how they are connected.

Common examples of network nodes include:

• Computers and laptops
• Smartphones and tablets
• Servers
• Network printers
• Switches
• Routers
• Firewalls

Some nodes are used by people to access services, while others provide services, connect multiple devices, forward traffic, or protect the network.

The Main Network Devices

Several network devices appear repeatedly in CCNA networking. Understanding their basic purpose is important before learning more advanced topics.

Router: Connects different networks and forwards traffic between them.
Switch: Connects devices within the same local network, or LAN.
Firewall: Controls and filters network traffic according to security rules.
Server: Provides services or resources to other devices.
Client: Requests or uses a service provided by another device.

These roles are related, but they are not always permanent. For example, the same computer can act as a client when requesting a file and as a server when providing a file to another device.

Key Points to Remember

• A network allows connected devices to communicate and share resources.
• A node is a device that participates in a network.
• Clients request or use services.
• Servers provide services.
• Switches connect devices within a LAN.
• Routers connect different networks.
• Firewalls control and filter network traffic.

Interfaces and Cables

1. Network Interfaces and Ports

A network interface is the point where a device connects to a network. These interfaces are commonly called ports.

Switches usually have many ports because they connect multiple end devices such as computers, printers, and servers.

For example, a switch may provide 24 Ethernet ports, with each port providing a physical connection for a network cable.

Show a modern switch with many Ethernet ports and several PCs connected. Clearly label the ports.

2. RJ-45

RJ-45 is the common connector and port used for many copper Ethernet connections.

You can find RJ-45 ports on computers, switches, routers, and other network devices. The RJ-45 connector is attached to the end of a copper Ethernet cable.

Different cables may have different colors or designs, but compatible RJ-45 connectors fit into the corresponding Ethernet ports.

Show a close-up RJ-45 Ethernet port and an RJ-45 connector on a copper cable, with clear labels.

3. Ethernet

Ethernet is a collection of networking standards and technologies used for communication over local networks.

For this lesson, the important part is how Ethernet standards define physical connections, including cable types, interfaces, and supported speeds.

Why Network Standards Matter

Network devices need common rules so equipment from different manufacturers can communicate and connect correctly.

Standards define physical requirements such as connector shapes and cables, as well as logical communication rules such as IP.

Without common standards, a cable and a network device might not even be physically compatible.

Show devices from different manufacturers communicating successfully because they follow common physical and networking standards.

Bits and Bytes

Network speeds are measured in bits per second (bps). A bit is a binary value represented by 0 or 1.

Eight bits make one byte. Network bandwidth is normally expressed in bits, such as Mbps or Gbps, while storage and file sizes are commonly expressed in bytes.

1 kilobit = 1,000 bits; 1 megabit = 1,000,000 bits; 1 gigabit = 1,000,000,000 bits; 1 terabit = 1,000,000,000,000 bits.

Because one byte contains eight bits, a gigabyte contains eight times as many bits as a gigabit.

Show 8 individual bits grouped into 1 byte, and compare Mbps/Gbps with MB/GB.

Ethernet Standards for Copper

Many Ethernet standards are defined by the IEEE 802.3 family.

Common copper Ethernet standards include 10BASE-T at 10 Mbps, 100BASE-T at 100 Mbps, 1000BASE-T at 1 Gbps, and 10GBASE-T at 10 Gbps.

These twisted-pair Ethernet connections commonly support up to 100 meters under the standard's normal specifications.

The T in these names refers to twisted-pair cabling.

UTP Cables

UTP stands for Unshielded Twisted Pair. It is one of the most common copper Ethernet cable types.

A UTP cable contains four twisted pairs, giving eight copper wires in total.

The twisting helps reduce the effects of electromagnetic interference (EMI). The cable is called unshielded because it does not have a metallic shield around the wire pairs.

A typical RJ-45 connector has eight contact positions, matching the eight conductors in the cable.

Show a cutaway UTP cable with four twisted pairs, eight wires, the outer jacket, and an RJ-45 connector.

10BASE-T and 100BASE-T Pin Usage

10BASE-T and 100BASE-T traditionally use two wire pairs, which means four conductors are used.

For a PC-to-switch connection, the PC transmits on pins 1 and 2 and receives on pins 3 and 6. The switch uses the opposite arrangement.

Using separate transmit and receive pairs allows full-duplex communication, meaning both devices can send and receive data at the same time.

Show a PC connected to a switch with pins 1-2 and 3-6 clearly labeled as Tx and Rx.

Straight-Through Cables

A straight-through cable keeps the same pin numbers connected from one end to the other: pin 1 to pin 1, pin 2 to pin 2, and so on.

This works for traditional connections such as PC-to-switch and router-to-switch because the devices use opposite transmit and receive pin arrangements.

Show both ends of a straight-through cable with identical pin numbers connected directly across.

Crossover Cables

A crossover cable swaps the transmit and receive pairs between the two ends.

For example, pins 1 and 2 on one end connect to pins 3 and 6 on the other end. This allows devices with the same traditional transmit/receive arrangement to communicate.

Crossover cables were traditionally used for connections such as PC-to-PC, switch-to-switch, router-to-router, and PC-to-router.

Compare a straight-through and crossover cable. Clearly show the 1-2 and 3-6 pairs crossing on the crossover cable.

Auto MDI-X

Modern network devices commonly support Auto MDI-X.

Auto MDI-X detects the transmit and receive arrangement of the connected device and automatically adjusts the interface.

Because of this feature, modern devices can usually communicate without requiring you to choose between straight-through and crossover cables manually.

Understanding the traditional cable types is still important for CCNA knowledge and older equipment.

Show two switches connected with a straight-through cable and a visual explanation of Auto MDI-X automatically adjusting Tx/Rx.

1000BASE-T and 10GBASE-T

Gigabit Ethernet and 10-Gigabit Ethernet over copper use all four twisted pairs, which means all eight conductors are involved.

The additional pairs are 4-5 and 7-8.

In 1000BASE-T and 10GBASE-T, each pair can carry data in both directions. This contributes to the higher speeds of these standards.

Fiber-Optic Connections

Copper UTP is useful for many local connections, but its typical Ethernet distance limit of about 100 meters can be a problem for longer links.

Fiber-optic technology uses light instead of electrical signals and supports much longer distances.

Networking equipment commonly uses SFP transceivers for fiber connections. SFP means Small Form-factor Pluggable.

A duplex fiber connection normally uses separate fibers for transmitting and receiving data.

Show a switch with RJ-45 ports and SFP ports, an SFP transceiver inserted into a slot, and a duplex fiber cable with Tx/Rx labels.

A fiber-optic cable contains several layers. The core is the central glass section that carries light.

Cladding surrounds the core and helps keep the light inside the fiber.

A buffer provides additional protection, while the outer jacket protects the cable from the external environment.

Show a labeled cross-section with core, cladding, buffer, and outer jacket.

Multimode Fiber

Multimode fiber has a larger core than single-mode fiber, allowing multiple paths of light to travel through it.

It supports longer distances than typical UTP copper, but shorter distances than single-mode fiber.

Multimode fiber is generally less expensive than single-mode fiber because it can use less expensive transmitters.

Show a wide fiber core with several light paths traveling at different angles.

Single-Mode Fiber

Single-mode fiber has a much narrower core and is designed for light to travel primarily along a single path.

It supports much longer distances than UTP and multimode fiber.

Single-mode fiber is generally more expensive because it commonly uses laser-based transmitters and specialized components.

Compare multimode and single-mode fiber side by side, showing the different core sizes and light paths.

Common Fiber-Optic Standards

1000BASE-LX provides 1 Gbps fiber Ethernet and can operate over single-mode or multimode fiber, with distance depending on the fiber type.

10GBASE-SR provides 10 Gbps over multimode fiber and can support distances up to about 400 meters.

10GBASE-LR provides 10 Gbps over single-mode fiber and can support distances up to about 10 kilometers.

10GBASE-ER provides 10 Gbps over single-mode fiber and can support distances up to about 30 kilometers.

UTP vs Fiber-Optic

UTP copper cables are generally cheaper and are commonly used for connecting nearby end hosts to switches.

UTP connections are typically limited to about 100 meters and can be affected by electromagnetic interference.

Fiber-optic cables cost more but support much longer distances and use light instead of electrical signals.

Fiber connections use transceivers such as SFPs, which are generally more expensive than RJ-45 copper interfaces.

Fiber does not radiate an electrical signal in the same way copper does, which can provide an advantage in environments where signal leakage is a concern.

TCP/IP Model

1. What Is the TCP/IP Model?

TCP/IP is a family of networking protocols that allows devices to communicate across networks, including the Internet.

Protocols such as IP, TCP, UDP, and HTTP perform different parts of the communication process.

The TCP/IP model organizes networking functions into layers. Each layer has a specific responsibility, making it easier to understand how networking technologies work together.

The model is a practical framework. Different resources may use slightly different numbers or names of layers.

Create a clean five-layer TCP/IP stack showing Application, Transport, Internet, Local Network, and Physical.

2. Protocols and Standards

A protocol is a set of rules that defines how devices communicate and exchange data over a network.

Protocols can be thought of as languages used by computers. Devices need compatible rules to understand one another.

Early networks often used proprietary protocols designed for specific vendors. This made communication between different manufacturers difficult.

Modern networks rely on open, vendor-neutral standards. When devices follow the same standards, equipment from different manufacturers can communicate.

Show computers from different manufacturers communicating successfully because they use common standards.

3. A Short History of TCP/IP

The development of the networks that eventually became the Internet began in the 1960s.

ARPA funded ARPANET, which became operational in 1969 to connect computers at universities and research locations.

ARPANET originally used NCP, the Network Control Program.

In 1974, Vint Cerf and Bob Kahn began developing TCP as an internetworking protocol. It later evolved into the separate TCP and IP protocols.

ARPANET officially transitioned to TCP/IP on January 1, 1983.

TCP/IP became widely adopted because it was based on open standards and could operate over many types of networks.

4. Who Defines Networking Standards?

Networking standards are generally created by independent standards organizations rather than by one vendor.

The IEEE develops many local-network technologies. Ethernet is defined by IEEE 802.3, while Wi-Fi is defined by IEEE 802.11.

The IETF develops many important Internet protocols, including TCP, IP, UDP, HTTP, and DNS.

The IETF publishes standards in documents called RFCs, or Requests for Comments.

Standards organizations define the rules, while vendors such as Cisco implement those standards in their products.

Compare IEEE and IETF. Show IEEE → Ethernet 802.3 and Wi-Fi 802.11; IETF → TCP, IP, UDP, HTTP, DNS.

5. Why Use Layers?

Network communication involves many jobs: transmitting physical signals, delivering data on a LAN, routing between networks, maintaining end-to-end communication, and supporting applications.

A layered model groups related jobs together. Each layer has its own responsibility.

Each layer uses services from the layer below and provides services to the layer above.

Protocols generally belong to a particular layer. Together, protocols at different layers form a protocol stack.

Show five stacked layers with arrows showing services moving between adjacent layers.

6. The Mail-Delivery Analogy

A useful way to understand layers is to compare networking with sending a letter.

The letter contains the message. The envelope contains destination information, while the delivery system moves it through different transportation steps.

Different parts of the process focus on different information. The message focuses on its content, the envelope focuses on the destination, and the delivery system focuses on moving it toward the next stop.

Network layers work similarly: each layer performs its own task while cooperating with the other layers.

Show a letter traveling from a sender through two post offices to the recipient, with different information handled at each stage.

7. The Five-Layer TCP/IP Model

For this course, the TCP/IP model is divided into five layers:

1. Application — communication between network applications.
2. Transport — communication between application processes using port numbers.
3. Internet — communication between hosts across networks using IP addresses.
4. Local Network — delivery across a local network using technologies such as Ethernet and Wi-Fi.
5. Physical — transmission of bits as electrical, optical, or radio signals.

8. Example: PC Communicating With a Server

Imagine PC1 sending a web request to SRV1. PC1 runs a web browser, while SRV1 runs a web server and possibly other services.

The Application layer creates the request and defines its application format.

The Transport layer uses a port number to identify the correct service on SRV1.

The Internet layer uses the destination IP address so routers can move the packet toward SRV1.

The Local Network layer handles each local hop using technologies such as Ethernet and MAC addresses.

The Physical layer sends the bits as electrical, optical, or radio signals.

9. Layer 1 — Physical Layer

Layer 1 is responsible for sending and receiving bits as physical signals.

Signals can be electrical over copper, optical over fiber, or radio over wireless connections.

This layer covers physical characteristics such as cables, connectors, signal levels, link speeds, antennas, and network interface hardware.

Examples include UTP cables, fiber-optic cables, Wi-Fi radios, antennas, and network interface cards (NICs).

Show UTP, fiber, Wi-Fi radio signals, and a NIC connected to a Layer 1 label.

10. Layer 2 — Local Network Layer

Layer 2 provides hop-to-hop delivery on a local network.

A hop is one step between two devices on a path. For example, PC1 → R1 is one hop, R1 → R2 is another, and R2 → SRV1 is a third.

Switches connect devices within a LAN and forward frames, but the switch itself is not counted as a hop in this example.

Layer 2 uses MAC addresses to identify network interfaces.

Important Layer 2 technologies for the CCNA include Ethernet and Wi-Fi.

Show PC1 → R1 → R2 → SRV1 and highlight the three hops, with switches shown as LAN connection devices.

11. Layer 3 — Internet Layer

Layer 3 provides end-to-end delivery between hosts across multiple networks.

It uses IP addresses to identify source and destination hosts.

Routers mainly operate at this layer by examining destination IP information and forwarding traffic toward the destination.

Important CCNA Layer 3 protocols include IPv4, IPv6, and ICMP.

A simple way to remember Layer 3 is: IP addresses and routers.

Show PC1 sending a packet toward SRV1 through two routers, with source and destination IP addresses labeled.

12. Layer 4 — Transport Layer

Layer 4 provides communication between application processes on different hosts.

A server may run multiple services at the same time. Port numbers identify which service should receive incoming data.

For example, a web service may use port 80, while traditional FTP uses port 21.

A transport port is a logical number identifying a process or service; it is not a physical network port.

The two major Transport-layer protocols for the CCNA are TCP and UDP.

Show one server running multiple services and demonstrate how different port numbers identify the correct application.

13. Layer 5 — Application Layer

Layer 5 is where network communication interacts with applications.

It defines how application processes format, send, and interpret network data.

HTTP and HTTPS are used for web communication, while FTP and TFTP are examples of file-transfer protocols.

Routers and switches normally do not need to understand Application-layer details. The end hosts interpret the application data.

Show a web browser communicating with a web server using HTTP/HTTPS.

14. Encapsulation

When data is sent, it moves down the protocol stack and each layer adds information needed for its task.

The Transport layer adds information such as source and destination port numbers.

The Internet layer adds source and destination IP addresses.

The Local Network layer adds a Layer 2 header and trailer, including MAC addressing and error-checking information.

The Physical layer transmits the resulting bits as signals.

This process of adding layer-specific information while data moves down the stack is called encapsulation.

Show Data → Transport header → IP header → Ethernet header/trailer → Bits/signals.

15. Decapsulation

The receiving device gets the transmitted bits and passes them upward through its protocol stack.

Layer 2 examines and removes its header and trailer. Layer 3 removes its IP header, and Layer 4 removes its transport header.

The original application data eventually reaches the Application layer.

Decapsulation is essentially encapsulation performed in reverse.

Show a receiving server removing Layer 2, Layer 3, and Layer 4 information until the original data reaches the application.

16. Protocol Data Units (PDUs)

Data has different names as it moves through the layers.

At Layer 4, TCP data plus its header is called a segment. UDP data plus its header is called a datagram.

At Layer 3, the transport information plus the IP header is called a packet.

At Layer 2, the packet plus the Ethernet header and trailer is called a frame.

These are also called Protocol Data Units (PDUs): Layer 4 PDU = segment/datagram, Layer 3 PDU = packet, Layer 2 PDU = frame.

The payload is the information carried inside a PDU, excluding that layer's own header and trailer.

Create a flow: Data → Segment/Datagram → Packet → Frame → Bits. Label L4, L3, L2, and Physical transmission.

17. Adjacent-Layer Interaction

Each layer provides a service to the layer directly above it and receives services from the layer directly below it.

Layer 4 uses port numbers to deliver data to the correct application. Layer 3 uses IP addresses to deliver data to the correct host. Layer 2 uses MAC addresses to deliver a frame to the next hop. Layer 1 transmits bits as physical signals.

This relationship is called adjacent-layer interaction.

Show the five layers with arrows between adjacent layers and a short service description for each.

18. Same-Layer Interaction

Same-layer interaction describes the logical communication between corresponding layers on different devices.

For example, Application-layer communication occurs between applications on the two end hosts.

Transport information identifies the destination application, IP information identifies the destination host, and MAC information identifies the next hop.

The layers cooperate inside each device while supporting communication between corresponding layers.

Show two hosts with matching TCP/IP layers and horizontal arrows between corresponding layers.

19. Why Layer Separation Matters

One major advantage of a layered architecture is flexibility.

A protocol at one layer can often be changed without redesigning every other layer.

For example, an application can use a different application protocol while the lower layers continue using IP and Ethernet. Likewise, Ethernet can be replaced with Wi-Fi without changing the higher layers.

This modular design makes networks easier to develop, replace, and troubleshoot.

Show the same application communication working over Ethernet and Wi-Fi while the upper layers remain unchanged.

20. TCP/IP and the OSI Model

The OSI model is another important networking reference model. It has seven layers: Application, Presentation, Session, Transport, Network, Data Link, and Physical.

TCP/IP became the dominant protocol suite used in real-world networks, while OSI remains widely used for teaching and describing networking layers.

In a common five-layer comparison, TCP/IP Application broadly corresponds to OSI Layers 5–7, Transport to Layer 4, Internet to Layer 3, Local Network to Layer 2, and Physical to Layer 1.

Many networking resources use the names Network for Layer 3 and Data Link for Layer 2. In practice, engineers commonly refer to these simply as Layer 3 and Layer 2.

• The five layers used here are Application, Transport, Internet, Local Network, and Physical.
• Layer 1 handles physical signals and media.
• Layer 2 provides hop-to-hop delivery and uses MAC addresses.
• Layer 3 provides host-to-host delivery across networks and uses IP addresses.
• Layer 4 provides process-to-process communication using port numbers; TCP and UDP are key protocols.
• Layer 5 handles communication between applications.

Network Fundamentals › VLAN

VLAN (Virtual LAN)

A VLAN (Virtual Local Area Network) is a logical grouping of devices within a physical network. It allows you to separate a switch into multiple broadcast domains, improving performance and security.

Why Use VLANs?

VLANs reduce broadcast traffic, improve security by isolating departments, and allow flexible network design without changing physical cabling.

Example

You can put the HR department on VLAN 10 and the IT department on VLAN 20 — even if they are connected to the same switch.

Network Fundamentals › Subnetting

Subnetting

Subnetting is dividing a larger network into smaller, more manageable sub-networks. It helps reduce congestion and improves security.

Example

The network 192.168.1.0/24 can be divided into smaller subnets like 192.168.1.0/26, creating 4 subnets with 64 addresses each.

Network Fundamentals › OSI Model

OSI Model

The OSI (Open Systems Interconnection) model is a 7-layer framework that standardizes how network devices communicate.

The 7 Layers

Physical, Data Link, Network, Transport, Session, Presentation, and Application.

IP Connectivity › Routing Basics

Routing Basics

Routing is the process of forwarding packets between different networks. Routers use routing tables to determine the best path for data.

IP Connectivity › OSPF

OSPF (Open Shortest Path First)

OSPF is a link-state routing protocol that calculates the shortest path to a destination using Dijkstra's algorithm.

Security Fundamentals › Firewalls

Firewalls

A firewall is a network security device that monitors and filters incoming and outgoing traffic based on security rules.
